Agentic software factories run on a harness

Spec Kit, Kiro, BMAD and Agentic DevOps converge on the same practices. Agentic Loop builds them in, so the model is not the only thing you rely on.

  1. Artifacts over chatSpecs, plans and progress live in your repo, not in a context window.
  2. Specialized agentsEach phase has its own role, context and definition of done.
  3. Verification is a loopTests, reviews and evaluations repeat until the gate passes or you decide.
  4. People at the gatesYou approve the spec and the deployment. Agents do the work in between.
  5. Guides and sensorsSkills steer agents before they act; tests and evaluators check them after.

Sources: GitHub Spec Kit · Kiro specs · Harness engineering · Harnesses for long-running agents · Agentic DevOps

Install one plugin. The loop sets up the rest.

  1. Install 
    copilot plugin install agentic-loop@awesome-copilot
    Or add it from the awesome-copilot marketplace in GitHub Copilot App.
  2. Ask

    “Open the agentic loop”

    The skill checks the bundled agentic-loop-canvas and agentic-loop-workflow extensions, adds any that are missing and opens the canvas.
  3. Check

    The canvas opens on Setup

    It checks skills, Azure CLI, Azure Developer CLI and sign-in, and offers a fix for anything missing.

SDD workflow: four phases, you at the gates

  1. 1Specify
  2. Approve the spec
  3. 2Implement
  5. 3Verify
  6. Approve deployment
  7. 4Deploy

Phases run in sequence. Fresh-context agents hand off through files, not chat history. Implement builds disjoint workstreams in parallel.

Gates need evidence. An independent reviewer must pass every phase. After two fix loops, open issues come to you with the evidence.

Every run leaves a record. Phases, gate results and lessons are saved so the next run starts smarter.

1Phase 1: Specify

Write the contract before the code.

  • Turns your brief into one spec: EARS acceptance criteria, a frozen implementation contract and up to four workstreams.
  • Plans the Azure deployment after a read-only preflight: region, model quota, RBAC and cost drivers.
  • An independent reviewer checks both. Approving them authorizes the resources in the deployment plan.

Produces

  • docs/spec.md
  • .azure/deployment-plan.md
WHEN a claim photo is uploaded
THE SYSTEM SHALL extract the damage
  and cite the policy clause it used.

Gate: you approve the spec and plan

2Phase 2: Implement

Prove the integration, then build in parallel.

  • azd provisions the resource group, Foundry project and models with keyless access.
  • A minimal hosted agent, one toolbox skill and one MCP tool pass an integration checkpoint first.
  • Workstreams then build Responses API agents (GitHub Copilot SDK or Microsoft Agent Framework), tools, knowledge and the app against the contract.

Produces

  • azure.yaml, infra/ and src/
  • docs/implementation.md
  • .env: FOUNDRY_PROJECT

Gate: provisioned, checkpoint proven, tests pass

3Phase 3: Verify

Cheap checks first, judgment second.

  1. ComputationalEvery component runs locally against Azure. Unit, contract and end-to-end tests cover each acceptance criterion.
  2. InferentialA fresh-context reviewer checks the evidence against the spec. Foundry evaluators score task adherence and intent resolution, plus groundedness for grounded agents.
  3. HumanAfter two fix loops, open issues come to you with the evidence.

Produces

  • docs/verify.md
  • tests/ and evaluation results
  • .env: LOCAL_FRONTEND

Gate: criteria, evaluations and traces pass, or you decide

4Phase 4: Deploy

You decide what goes live.

  • You review the verification evidence and approve going live.
  • azd up reconciles the infrastructure, then deploys agents and apps with managed identity, least-privilege RBAC and Application Insights.
  • Health checks, a call to each hosted agent and the end-to-end tests run against the deployed endpoints. Results and URLs land in docs/deploy.md.

Runs

azd up
# health, agents and E2E, then DEPLOYED_FRONTEND
azd down --purge   # when you finish

Gate: you approve before azd up

Follow every run from the canvas

  • Phases, agents, gate results and artifacts update live.
  • Approve, request changes or cancel without leaving the canvas.
  • A paused run says what it needs. A failed gate shows its evidence, with Fix in Chat or Resume and retry.
  • While Copilot works, a tip dock teaches Microsoft Foundry: hosted agents, toolbox, evaluations and tracing.

Every run improves the next one

  • Each run writes a flight record, and its lessons go to LOOP.md.
  • Improve the loop analyzes past runs and proposes edits to the skill and the workflow.
  • Every change is a diff you review, checked against evals. Approvals, RBAC, safety and evidence gates are never weakened.

Opinionated defaults, firm guardrails

Defaults

  • Hosted agents on the Responses API
  • GitHub Copilot SDK for skills, Agent Framework for workflows
  • Python 3.13 and gpt-5.4-mini
  • Foundry toolbox tools and Foundry IQ knowledge
  • Tracing in Application Insights
  • eastus2, or swedencentral for EU data

Guardrails

  • Keyless: managed identity and Azure RBAC
  • Your approval before the spec and the deployment
  • Bounded fix loops and run limits
  • Fresh-context reviewers
  • Every artifact lives in your repo
  • Self-improvements are reviewable and revertible
